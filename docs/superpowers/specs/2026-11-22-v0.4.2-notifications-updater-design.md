# Energy Accounting v0.4.2 — Notification Permission, Icon and Update Dialog

## 1. Intent and Why

v0.4.1 is installed. Three user-visible defects remain:

1. **Notification permission is never requested on first open** when reminders were enabled by a restored backup. The only prompt lives in the reminder toggle/test buttons in Manage & Export, so a restored set of enabled reminders schedules silently; the receiver then suppresses every notification because notifications are not allowed.
2. **The status bar shows a circle-plus** instead of the app mark. `ic_notification.xml` is a circle-with-plus vector and is used as the notification small icon. The expanded notification shows the app icon, which is why the two surfaces disagree.
3. **The update dialog is ugly and shows raw Markdown.** `ReleaseNotes` renders `Text(info.releaseNotes)` directly. The centered `Dialog`/`Card` has no height constraint, so the raw `#`, `**` and `-` text overflows behind the action buttons.

This design fixes all three in a v0.4.2 patch and keeps the public updater working.

## 2. Findings

- `ManageExportScreen.kt:262-279` contains the only `POST_NOTIFICATIONS` launchers. They are reached only from `ReminderRow` toggles (`:463-480`) and **Send test notification** (`:488-505`). Restored reminders (`ManageExportViewModel.restore`, `:274-281`) are scheduled without any permission check.
- `CheckInReminderReceiver.kt:125,154` silently returns when `areNotificationsEnabled()` is false; there is no user-facing recovery path outside the hidden Developer Mode status.
- `ic_notification.xml` is a 24 dp circle-plus path (`M13,17h-2v-4H7v-2h4V7h2v4h4v2h-4v4z`). `CheckInReminderReceiver.kt:200` uses it as `setSmallIcon`.
- `UpdateDialog.kt` uses a centered `Dialog` with a `Card` (`fillMaxWidth(0.92f)`, no height cap). `ReleaseNotes` (`:118-136`) uses `Text(notes)` inside a 180 dp scroll box. There is no Markdown parser or library in the project.
- The v0.4.1 release body is Markdown with `#`/`##` headings, `**bold**`, bullets, and wrapped lines; the old dialog displays those markers literally.

## 3. Goals

- Request `POST_NOTIFICATIONS` automatically on first open when at least one reminder is enabled, including immediately after a backup restore.
- Ask once per install; if denied, show a visible warning card in the reminders section with **Allow notifications** / **Open notification settings**.
- Replace the status-bar notification icon with a white bolt derived from the app's launcher mark; keep the expanded notification's app icon.
- Replace the update prompt with a Material 3 `ModalBottomSheet`, consistent with Add Entry and Calendar.
- Render a small, controlled Markdown subset in the update dialog: headings, bold, bullets, paragraphs, links. Do not add a Markdown dependency.
- Constrain the dialog height and make the notes scroll while Later/Update stay visible.
- Ship the fixes as private-then-public `v0.4.2`, versionCode `402`, same signing key, APK + `SHA256SUMS`.

## 4. Non-Goals

- No change to the applicationId, namespace, Kotlin packages, keystore alias, or certificate DN.
- No new notification channel or notification behavior beyond the icon; no reminder scheduling logic changes.
- No full Markdown implementation: no tables, nested lists, HTML, or code fences beyond the documented subset.
- No package/signing identity changes and no rewriting of v0.3.0/v0.4.0/v0.4.1 tags or assets.
- No redesign of the Manage screen or other dialogs.

## 5. Decisions

### 5.1 Notification permission

- Add a pure predicate in `ui/common/NotificationPermission.kt`:
  ```kotlin
  internal fun shouldRequestNotificationPermission(
      sdkInt: Int,
      permissionGranted: Boolean,
      reminders: List<CheckInReminder>,
  ): Boolean = sdkInt >= Build.VERSION_CODES.TIRAMISU &&
      !permissionGranted &&
      reminders.any { it.isEnabled }
  ```
- `AppSettings` gains `notificationPermissionPrompted(): Boolean` and `setNotificationPermissionPrompted(Boolean)`, stored under a new preference key. It is device ergonomics and is not part of backups.
- In `MainActivity`, collect `manageViewModel.reminders`. After composition, if `shouldRequestNotificationPermission(...)` and the prompt flag is false, set the flag and launch `ActivityResultContracts.RequestPermission()` for `POST_NOTIFICATIONS`. This covers first open and the state after a restore because the reminders flow emits again.
- Android 12 and older skip the runtime request.
- In `ManageExportScreen`, show a notification warning card inside the Check-in Reminders section when at least one reminder is enabled and `NotificationManagerCompat.areNotificationsEnabled()` is false. The card shows:
  - the existing rationale text (or a new short body),
  - **Allow notifications** when the runtime permission is missing (launches the permission request),
  - **Open notification settings** otherwise (`Settings.ACTION_APP_NOTIFICATION_SETTINGS` with the app package).
- Add English and Italian strings in `app/translations.json`; let `syncTranslations` regenerate the XML.
- The existing toggle/test launchers remain and still work; the app-level prompt is a one-time safety net, not a replacement.

### 5.2 Notification icon

- Replace `app/src/main/res/drawable/ic_notification.xml` with a 24 dp white bolt vector using the app's Lucide zap geometry:
  ```xml
  <path android:fillColor="#FFFFFFFF"
      android:pathData="M15.914 4a1.5 1.5 0 0 0 -2.474 -1.561l-9 9A1.5 1.5 0 0 0 5.5 14h4.002a.5.5 0 0 1 .471.666L8.086 20a1.5 1.5 0 0 0 2.475 1.56l9 -9A1.5 1.5 0 0 0 18.5 10h-3.997a.5.5 0 0 1 -0.472 -0.667z" />
  ```
- Keep `setSmallIcon(R.drawable.ic_notification)` unchanged. Android renders it as a monochrome status-bar silhouette; the expanded notification continues to use the app icon.
- Verify with **Send test notification** on API 35: status bar shows the bolt; expanding shows the app icon.

### 5.3 Update dialog

- Add `ui/update/ReleaseNotesMarkdown.kt` with:
  - `sealed interface ReleaseNoteBlock`:
    - `data class Heading(val level: Int, val text: String)`
    - `data class Paragraph(val text: String)`
    - `data class Bullet(val text: String)`
  - `internal fun parseReleaseNotes(markdown: String): List<ReleaseNoteBlock>`:
    - skip a leading `# …` title (the dialog already shows the version),
    - map `##`/`###` to headings,
    - map `- ` / `* ` lines to bullets, appending wrapped continuation lines,
    - join wrapped paragraph lines with spaces,
    - ignore blank lines outside blocks.
  - `internal fun renderInlineMarkdown(text: String): AnnotatedString`:
    - `**bold**` → `SpanStyle(fontWeight = FontWeight.SemiBold)`,
    - `[label](url)` → `LinkAnnotation.Url(url)` plus the label text; leave malformed markers as literal text.
  - `@Composable fun ReleaseNotesMarkdown(notes: String, modifier: Modifier = Modifier)` renders headings, paragraphs, and bullet rows; links use `LocalUriHandler`.
- Redesign `UpdateDialog` as a `ModalBottomSheet`:
  - `rememberModalBottomSheetState(skipPartiallyExpanded = true)`,
  - header icon/title, version subtitle, "What's new" label, scrollable `ReleaseNotesMarkdown` capped at a screen-relative height,
  - a divider and a sticky Later/Update row; other states (Downloading, Verifying, Permission, Installing, Error) keep their existing actions in the same sheet,
  - `onDismissRequest` keeps the existing Later behavior.
- The v0.4.2 notes are written short and plain enough that the **old v0.4.1 dialog** can display them acceptably for the one update before the new dialog is installed.

### 5.4 Release

- `v0.4.2`, `versionCode 402`, same RSA 4096 release key, public release.
- Add `docs/release-notes/v0.4.2.md`; the release workflow uses it as the body.
- Update the README install line to say “install the latest APK once” instead of naming v0.4.1.
- Tag `v0.4.2` from merged master; verify APK version, icon, certificate, SHA256SUMS, and release body.

## 6. Verification

- Unit tests:
  - `shouldRequestNotificationPermission` across SDK 32/33, granted/denied, enabled/disabled reminders.
  - `AppSettings` prompt flag persists.
  - `parseReleaseNotes` skips the leading H1, maps headings/bullets/paragraphs, joins wrapped lines, and never leaves raw `#`/`**`/`-` in block text.
  - `renderInlineMarkdown` produces a bold span and a URL link annotation.
- Compose tests:
  - `ReleaseNotesMarkdown` shows a heading and bullet text, with no literal `#`/`**`.
  - Existing `ManageExportScreen` tests still compile/pass; the warning card is behind a permission/manifest state and is verified manually.
- Manual API 35:
  - Clear app data, restore `synthetic-data/energy-accounting-demo-backup.json` (all reminders enabled), open the app → permission prompt appears.
  - Grant → **Send test notification** → status bar bolt; expanded notification shows the app icon.
  - Deny → Manage shows the warning card; **Open notification settings** reaches the app notification settings.
  - Open the update dialog with the v0.4.1 notes → headings/bold/bullets formatted, no raw Markdown, notes scroll, buttons stay visible.
  - v0.4.1 → v0.4.2 through the app; verify download/checksum/signature/installer and the new sheet.
- Full `./gradlew :app:testDebugUnitTest :app:assembleDebug`; instrumentation where relevant; CI and release workflow green.
- Release: `401`→`402`, same certificate, checksum verifies, body has no old wording, public assets.

## 7. Risks

- Asking on first open can be intrusive if no reminder is enabled; condition on any enabled reminder and persist the one-time flag.
- A denied permission cannot be re-prompted by the system after “don’t ask again”; the warning card must open app notification settings.
- The status bar icon must remain legible at 24 dp; a solid bolt is safer than the detailed brain outline. The expanded app icon is unchanged.
- The Markdown parser must not mangle links or emphasis; keep the supported subset small and test it.
- A long release note can overflow a small screen; the sheet must cap height and scroll the notes, not the whole dialog.
- The old v0.4.1 dialog will show the v0.4.2 notes raw; keep those notes short and use them as the last compatibility check.
