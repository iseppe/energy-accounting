# Energy Accounting v0.4.2 — Notification Permission, Icon and Update Dialog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the missing notification-permission prompt, the circle-plus status-bar icon, and the raw-Markdown/overflowing update dialog, then ship a public `v0.4.2` patch.

**Architecture:** Add a pure permission predicate plus an app-level one-shot prompt driven by the reminders flow; add a warning card in Manage. Replace the notification small icon with a 24 dp white bolt. Add a small Markdown-subset parser and render it in a Material 3 bottom sheet with a height-capped, scrollable notes area and sticky actions.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, AndroidX Activity Result, Room/Flow, Robolectric/JUnit, Compose UI tests, GitHub Actions release workflow.

**Spec:** `docs/superpowers/specs/2026-11-22-v0.4.2-notifications-updater-design.md`

## Global Constraints

- `applicationId`/namespace `com.empathie.energyaccounting`, internal Kotlin packages/imports, keystore alias `empathie`, and certificate DN `CN=Empathie Energy Accounting, O=Empathie, C=IT` must not change.
- No new third-party dependency for Markdown; use Compose `AnnotatedString`.
- `minSdk 26`; the runtime notification permission applies only on Android 13+ (`TIRAMISU`).
- English and Italian strings must both be added; `app/translations.json` is the source, `syncTranslations` regenerates the XML.
- No change to notification scheduling, channels, reminder behavior, or the update verification protocol.
- `v0.4.2` is `versionCode 402`, same release key, public APK + `SHA256SUMS`; v0.3.0/v0.4.0/v0.4.1 tags/assets stay untouched.
- All tests and builds must pass before each commit; docs changes still get a build check.

## Review Focus

1. **First open after restore** — reminders enabled by a backup must trigger the permission prompt even though no switch was toggled; denial must leave a visible settings path, not silence.
2. **System-denied state** — permission already denied (“don’t ask again”) must not loop the prompt; the Manage card opens app notification settings.
3. **Status-bar legibility** — the 24 dp monochrome bolt must be visible at status-bar size; the expanded notification must keep the full app icon.
4. **Long release notes** — the bottom sheet must cap its height, scroll only the notes, and keep Later/Update visible on small screens and in both themes.
5. **Old-dialog compatibility** — the installed v0.4.1 dialog will display the v0.4.2 notes raw for one update; the notes must stay short and readable before the new dialog is installed.

After the composition starts, add:
```kotlin
LaunchedEffect(reminders) {
    if (Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU) return@LaunchedEffect
    val granted = ContextCompat.checkSelfPermission(
        this@MainActivity,
        Manifest.permission.POST_NOTIFICATIONS,
    ) == PackageManager.PERMISSION_GRANTED
    if (shouldRequestNotificationPermission(Build.VERSION.SDK_INT, granted, reminders) &&
        !app.settings.notificationPermissionPrompted()
    ) {
        app.settings.setNotificationPermissionPrompted(true)
        requestNotificationPermission.launch(Manifest.permission.POST_NOTIFICATIONS)
    }
}
```
